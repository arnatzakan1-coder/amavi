# AMAVI — персональная парфюмерная студия

Сайт парфюмерной студии AMAVI (Алматы): анкета и запись к одному из трёх парфюмеров, закрытый раздел студии для парфюмеров (анкеты, конструктор формул, сравнение с нишевыми ароматами), конфиденциальные формулы клиентов с повторным заказом онлайн, личный кабинет, страница студии с 2GIS и админ-панель. Языки: русский, казахский, английский.

**Стек:** Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · Framer Motion · React Three Fiber · Auth.js v5 · Drizzle ORM + libSQL (SQLite локально, Turso в продакшене) · dnd-kit · Zod.

## Быстрый старт

```bash
npm install
cp .env.example .env          # заполните AUTH_SECRET и ADMIN_EMAILS
npm run db:setup              # создаёт таблицы и загружает данные (или просто npm run dev — база создастся сама)
npm run dev                   # http://localhost:3000
```

1. Зарегистрируйтесь на `/register` с почтой из `ADMIN_EMAILS` — аккаунт сразу получит роль администратора (или выполните `npm run make-admin -- you@mail.kz`).
2. Откройте `/admin` → «Обзор» — там список всего, чего не было в файлах и что нужно заполнить.

Проверки: `npm test` (композиция, цены, сравнение, телефон, слоты записи), `npm run typecheck`, `npm run build`.

## Как устроена работа студии

- **Клиент**: анкета (возраст, любимые направления, повод, любимые/нежелательные ингредиенты, пожелания, название аромата) → выбор одного из трёх парфюмеров и свободного 90-минутного слота (`/book`) → предоплата 50 % по счёту Kaspi от менеджера. Занятый слот сразу становится недоступным (уникальный индекс в базе исключает двойную запись).
- **Парфюмер** (роль `PERFUMER`, раздел `/studio`): видит записи и анкеты до встречи; после сессии открывает конструктор из записи и сохраняет формулу за клиентом.
- **Формулы конфиденциальны**: состав видят только парфюмеры и администраторы. Клиент в «Мои формулы» видит название аромата, историю заказов и может повторить заказ (только самовывоз). Новый аромат онлайн создать нельзя.
- Имена парфюмеров и их график — «Админ → Парфюмеры и график» (сейчас стоят заглушки «Парфюмер 1–3»).

Координаты и ссылку на карточку 2GIS введите в «Админ → Студия и 2GIS».

## Что нужно подключить

| Функция | Что предоставить | Куда |
|---|---|---|
| Вход через Google | OAuth Client ID/Secret, redirect `<APP_URL>/api/auth/callback/google` | `AUTH_GOOGLE_*` |
| Вход через Apple | Services ID + секрет, return URL `<APP_URL>/api/auth/callback/apple` | `AUTH_APPLE_*` |
| Карта 2GIS | ключ MapGL с dev.2gis.com + координаты в админке | `NEXT_PUBLIC_2GIS_API_KEY` |
| Kaspi / Halyk / карта Visa·Mastercard | договор эквайринга и ключи мерчанта | `src/lib/payments.ts` + env |

**Оплата.** Сайт не имитирует платежи и не хранит данные карт. Онлайн-методы (Kaspi, Halyk, карта) показаны как «подключается», пока в `src/lib/payments.ts` не реализованы `createPayment` и `verifyWebhook` по официальной документации провайдера и не заданы ключи; затем замените `isReady: () => false` на `hasEnv(env)`. Результат оплаты принимает `POST /api/payments/<provider>/webhook` (подпись проверяет адаптер, повторные уведомления безопасны).
Сразу работают два ручных способа: **«Kaspi: счёт на номер телефона»** (менеджер выставляет счёт в Kaspi Pay после подтверждения) и **«Оплата в бутике»** (только при самовывозе). Статус «Оплачен» администратор ставит в карточке заказа.

## Деплой (Vercel + Turso)

Команды запускать не нужно: при первом старте сайт сам создаёт таблицы (`drizzle/`) и загружает данные, если база пустая (`src/instrumentation.ts` → `src/db/bootstrap.ts`).

1. Загрузите проект в репозиторий GitHub.
2. Vercel → **Add New → Project** → выберите репозиторий.
3. В проекте Vercel: **Storage → Marketplace → Turso → Create / Connect**. Интеграция сама добавит `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN`.
4. **Settings → Environment Variables**: `AUTH_SECRET` (случайная строка 32+ символов) и `ADMIN_EMAILS` (ваша почта).
5. **Deploy**. После деплоя зарегистрируйтесь на сайте с почтой из `ADMIN_EMAILS` — откроется `/admin`.

Локальный файл SQLite на Vercel не подходит: файловая система там временная, поэтому нужна Turso. Любой Node-хостинг с постоянным диском тоже подойдёт (`npm run build && npm start`).

## Безопасность и данные

- Цена заказа и валидность формулы всегда пересчитываются на сервере; клиентские суммы — только для отображения.
- Формулы, адреса и заказы доступны только владельцу (проверка `userId` в каждом запросе); роль администратора проверяется по базе в каждом admin-действии.
- Пароли — bcrypt; сессии — подписанные JWT (Auth.js). Согласие на обработку персональных данных фиксируется в заказе.
- Форма вопросов: honeypot и ограничение 5 сообщений / 10 мин на IP.
